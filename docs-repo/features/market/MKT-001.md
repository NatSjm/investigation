# MKT-001 — Market scenarios

> **Skeleton** — generated from the graph neighbourhood of context `market`; business rules to be completed from
> `MarketManager.kt` and the Scenarios page.

## Summary
On the **Scenarios** page (`/session/:sessionId/scenarios`) the representative and the client create named
scenarios (`market_scenario`) consisting of shocks — from a given month, a price change and a transport price change
in percent — applied on top of the **baseline curve** that `market-data` delivers into `baseline_price` and refreshes
through `harbor.market.prices-updated`. Scenarios belong to the session and are consumed by the stress test
([STR-001](/features/stress/STR-001.md)) via [scenario_price_path](/domain/calculations/scenario_price_path.md).

## Actors
| Actor | Role in this feature |
|---|---|
| Representative | Creates, edits, deletes scenarios |
| Client | Proposes shocks during the meeting |
| market-data (external) | Baseline price and transport price curve |

## Business rules
- **BR-MKT-001-1** — A scenario MUST belong to exactly one session and MUST have a non-empty unique `name` within
  that session; `createScenario` with a duplicate name MUST return `409`.[^manager] (source: code manager#createScenario)
- **BR-MKT-001-2** — Each shock MUST have `fromMonth` inside the session horizon and `priceChangePct` /
  `transportChangePct` greater than −1; shocks are applied cumulatively from `fromMonth` on.[^manager] (source: code manager#MarketManager)
- **BR-MKT-001-3** — On `harbor.market.prices-updated` for the session's product group and corridor the listener
  MUST refresh `baseline_price` from `market-data` (`GET /prices/...`, `GET /transport-prices/...`).[^listener] (source: code listener#onPricesUpdated)
