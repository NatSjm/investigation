# RPT-001 — Meeting report and PDF

> **Skeleton** — generated from the graph neighbourhood of context `reports`; to be completed from `ReportManager.kt`.

## Summary
When a session closes ([SES-001](/features/meetings/SES-001.md)), the reports context assembles the **report
payload** (client, role, four projection tables, cover ratio, scenarios, stress test results) into
`meeting_report.payload`, publishes `harbor.reports.render-requested` and, on `harbor.reports.rendered`, stores the
`pdf_path`. The **Meetings** page shows a **Download PDF** button once the report is rendered; `regenerateReport`
rebuilds the payload and re-requests rendering.

## Actors
| Actor | Role in this feature |
|---|---|
| Representative | Downloads or regenerates the report |
| document-service (external) | Renders the PDF |
| meetings context | Triggers the report by `session-closed` |

## Business rules
- **BR-RPT-001-1** — On `harbor.meetings.session-closed` the listener MUST write `meeting_report(session_id, payload,
  status = REQUESTED)` and publish exactly one `harbor.reports.render-requested` with `payloadRef`.[^manager]
- **BR-RPT-001-2** — On `harbor.reports.rendered` the listener MUST set `pdf_path`, `rendered_at` and
  `status = RENDERED`; `downloadReportPdf` MUST return `404` while `status != RENDERED`.[^manager]
- **BR-RPT-001-3** — `regenerateReport` MUST be allowed only for `CLOSED` sessions and MUST overwrite `payload`
  while keeping the previous `pdf_path` until the new rendering arrives.[^manager]
